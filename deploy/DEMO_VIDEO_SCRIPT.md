# 3 分钟演示视频录制脚本（活链接兜底）

> 录制工具：OBS Studio（免费）或 Windows 自带录屏（Win+G）。
> 本地跑**真实模型**（ollama / qwen2.5:7b）最有效果——真 AI 产出 vs 线上 Mock。
> 录制前先跑一遍流程预热，避免现场翻车。

## 准备（5 分钟）

```bash
cd "E:/第287期-仿百度文库的在线文库管理系统/ai-content-factory"
# 1. 确保 .env 是 ollama（真模型）
# 2. 启动后端 + 前端
./.venv/Scripts/python.exe -m uvicorn app.main:app --port 8000 &
./.venv/Scripts/python.exe -m streamlit run frontend/app.py &
# 3. 浏览器打开 http://localhost:8501，先手动点一遍"模板拆解 + 内容生成"预热
```

## 分镜脚本（总时长 ~3 分钟）

### 0:00 - 0:15 开场白（口播）
> "这是一个把商品信息转成可发布带货内容的多 Agent 系统。它复刻了专业内容团队的工作流：定方向、拆爆款、写稿、过审。下面我用一个面霜商品演示。"

### 0:15 - 1:00 模板拆解（核心卖点）
- 切到「模板拆解」Tab
- 粘贴一段竞品爆款文案（提前准备）
- 点「开始拆解」→ 展示七维表（标题公式/开头钩子/内容骨架/CTA）
- 口播："这里是核心能力——把任何爆款拆成可复用的模板结构。"

### 1:00 - 2:00 内容生成（5-Agent 闭环）
- 切到「内容生成」Tab，填入：
  商品：玻尿酸保湿面霜 / 护肤 / 卖点（深层补水、成分温和、性价比高）/ 干皮女性
- 点「生成」→ 展示成稿标题 + 正文 + 配图提示词 + 标签
- 展开「Agent 执行日志」，逐条展示 Supervisor→选题→模板→脚本→审核
- 口播："5 个 Agent 依次协作，每步中间产物都能看到——这就是可观测性。"

### 2:00 - 2:40 审核返修（加分点）
- 重新生成一次，在卖点里故意写"全网最低价"
- 展示审核 Agent 拦截 → 返修 → 输出合规版本
- 口播："电商内容有广告法约束，我设计了审核+返修循环，不通过自动修正。这证明多 Agent 架构比单次调用更鲁棒。"

### 2:40 - 3:00 收尾
> "技术栈 LangGraph + FastAPI + Streamlit，LLM 可插拔（本地 Ollama 已验证、可切 DeepSeek）。完整架构和设计文档我已准备，随时可以深入交流。"
